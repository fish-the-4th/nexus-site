Getting started

Add Nexus, put its role in the right place, and check that it answers. This takes about five minutes, and the role order is the step people most often skip.

1. Add Nexus

Use the invite link and pick your server. You need the Manage Server permission to add a bot.

Add Nexus Ask in the support server

The invite asks for the Administrator permission. That's deliberate: it means every feature works without a permission puzzle. If you'd rather give Nexus less, you can edit its role after it joins. A feature that needs a permission Nexus doesn't have will tell you which one is missing.

2. Put the Nexus role in the right place

Discord decides what a bot can do by its permissions and by where its role sits in the role list. A bot can only act on people and roles below its own role. That means Nexus can't ban, mute, or give a role to anyone who sits above it.

Open Server Settings, Roles and drag the Nexus role up so it sits above every role it needs to manage, but below your own admin roles.

PositionRoleWhy
TopOwner and admin rolesPeople Nexus should never act on
NextNexusNeeds to be above anything it moderates or hands out
Below thatModerator rolesModerators can act on members, and Nexus can act on them
BottomMember rolesWhat join roles and timed roles usually give out
If you do only one thing from this page, do this. When Nexus says "I can't do that to X, their role sits above mine", the role order is almost always the reason.

3. Check that it answers

In any channel Nexus can see, type:

You
-ping
Nexus
🏓 Pong! 38ms

If nothing comes back, check that Nexus can view and send messages in that channel, then see Troubleshooting.

4. Open the commands menu

Run -commands for a menu with a button for every category. Only you can see what comes up when you press a button, so it won't clutter the channel. -help gives a shorter set of tips and the support buttons.

How Nexus works

A handful of rules apply to every command. Knowing them makes the rest of the docs easier, and explains most of the "why did it say that" moments.

Commands and the prefix

A command is a prefix followed by a name and any details: -ban @Sam 7d spamming. The default prefix is -. Each server can set its own, and you can always mention Nexus instead (@Nexus ping).

Square brackets in the docs, like [user], mean "fill this in". Nexus reads the inputs in the order shown.

When a command asks for a user, a mention or a Discord ID always works. Most commands also accept a username. IDs are the safest choice when two people have similar names, and they're the only way to reach someone who isn't in the server.

Two permission checks

Every command that changes something goes through two checks.

1. Do you have permission?

Each command needs a Discord permission, like Kick Members or Manage Roles. Owners and administrators can use everything. The Commands page lists the permission for each command, and Command access lets admins change who can use what.

2. Does the role order allow it?

You can only act on someone whose top role is below yours. Nexus needs the same: its role must be above them. The server owner is exempt from the first rule.

When the role order blocks something, Nexus says so in the channel instead of failing quietly. See Troubleshooting if you hit it.

Cooldowns

Nexus runs on a small host with limited resources, so each person is limited in how fast they can run commands:

  • No two commands within 2 seconds of each other.
  • The same command can't be repeated within 3 seconds.

If you hit a limit, Nexus tells you how long to wait. It only affects you, never anyone else in the channel.

Cases

Kicks, bans, mutes, warnings and their reversals each create a case: a record with a number like A1B2-C3D4-E5F6. The member is sent a DM with the reason (if their DMs are closed, the action still goes through). Cases are kept per server, so one server can never see another's. The Cases and history page covers looking them up.

Direct messages

Nexus is built for servers. In a DM, only -ping, -commands and -help work. The one thing Nexus does send you privately is your own moderation history, when you run -myhistory in a server.

Timestamps

When Nexus shows a time, like when a reminder is due or a giveaway ends, it uses Discord's own timestamps. Everyone sees them converted to their own time zone automatically.

Blacklist

The Nexus owner can blacklist a user who abuses the bot. A blacklisted user gets a message the next time they try a command, and Nexus ignores them otherwise. If you think it's a mistake, ask in the support server.

Your server's data

Settings, cases and the rest are stored per server and stay until they're removed or the server's data is wiped. Activity stats and join records are deleted after 30 days. The privacy page lists exactly what is kept.

Common mistakes

  • A number with no unit. -reminder create 30 take a break doesn't say whether that's seconds, minutes or hours, so Nexus asks you to try again. Write 30m.
  • A space inside the time. 1h 30m is read as 1h followed by the reminder text "30m". Write 1h30m.
  • A unit the command doesn't know. Months only work for timed roles. For a reminder, use days (30d).
  • A time that's too long. Each command has a limit, shown above.

Set up a new server

A first-time setup that covers logs, AutoMod, welcome roles, tickets and the starboard. Plan on about fifteen minutes. You can stop after any step, and everything you've done so far keeps working.

Before you start

  • Add Nexus and move its role above the roles it manages. Getting started shows how.
  • You need to be the owner, an administrator, or have the Manage Server permission. Ticket setup needs Administrator.
  • Decide which channels staff should see. Log channels can contain the text of deleted messages, so keep them private.

1. Create the channels

Make these in your server first, so you can point Nexus at them. You can name them anything.

Make sure Nexus can view and send messages in every one of them.

2. Turn on logging

Logging sends each kind of event to a channel you choose. A good starting set is moderation, messages and users. You can add the rest later.

Run -logs afterwards to see every type and where it goes. The full list of types and what each one records is on the Logging page.

3. Turn on AutoMod

AutoMod has three protections. A level of 5 is a sensible starting point for each one.

You

The last line exempts your moderators, so AutoMod never deletes their messages. Other people are checked as normal. Protect your server explains what each level does and how to tune it.

4. Give new members a role

Join roles are handed out automatically when someone joins. The role must sit below the Nexus role.

You

You can list more than one role in the same command. Roles and autoroles also covers roles that come back when someone rejoins, and roles that expire.

Tickets give members a private channel with your support team. You need a support role, the category you made earlier, and the log channel.

You

If the category's name has spaces, put it in quotes or use its ID. Then go to the channel where members should ask for help, such as #support, and post the panel:

You
-ticket panel

Members press the button on that message to open a ticket. See Tickets for how it works day to day.

The starboard reposts messages that get a chosen reaction, so the best moments don't get buried.

Protect your server

How to set up AutoMod so it catches spam, scam links and raids without getting in the way of normal chat, and what to do if a raid actually happens.

What AutoMod protects against

Spam

Someone sends a burst of messages faster than a person normally would. Nexus removes the burst and tells them to slow down.

Scam links

A link that matches a known scam or look-alike domain. Nexus removes the message and warns the sender.

Raids

Many accounts join at once. Nexus locks the server down until you say it's over.

Each one is switched on separately with a level from 1 to 10, and 0 turns it off.

Choosing a level

Higher levels are stricter. Here is exactly what each level means for spam and raids.

LevelSpam: more than this many messagesRaids: this many joins or more
110 in 10 seconds20 in 30 seconds
29 in 10 seconds18 in 30 seconds
38 in 10 seconds15 in 30 seconds
47 in 10 seconds12 in 30 seconds
56 in 10 seconds10 in 30 seconds
65 in 10 seconds8 in 30 seconds
75 in 8 seconds6 in 20 seconds
84 in 8 seconds5 in 20 seconds
94 in 6 seconds4 in 15 seconds
103 in 5 seconds3 in 15 seconds

A rough guide to picking:

  • Small, friendly servers: level 3 or 4. Real people rarely trip it.
  • Typical public servers: level 5. A good default for all three.
  • Large or targeted servers: 7 or higher for raids, and watch the log closely, because fast chat in busy channels can reach the spam limit.

Scam link levels work differently. Higher levels match more look-alike domains, and from level 6 up they also flag links that use typical scam wording. That catches more, but it's also more likely to flag something harmless.

What happens when something is caught

Spam

When someone goes over the limit, Nexus deletes the messages from that burst (only those, not their older chat), posts "Slow down a bit" in the channel for a few seconds, and writes an entry in the AutoMod log. It doesn't mute or kick anyone. If Nexus can't delete the messages, the log entry says to check its Manage Messages permission.

Scam links

The message is deleted, the sender is told the link looked dangerous, and the log records what was posted. Edited messages are checked too, so changing a harmless message into a link afterwards doesn't get around it.

Raids

When enough accounts join inside the window, Nexus starts a lockdown:

  1. It switches off Send Messages for @everyone in every text channel, and remembers what each channel was set to before.
  2. It posts an alert in the server's system channel and writes to the AutoMod log.
  3. While the lockdown is active, anyone who tries to join is sent a short DM saying the server is on lockdown, then kicked.

A channel that was already locked is left alone. When you're ready to reopen, run:

You
-automod raidend

Every channel goes back to exactly how it was, including channels that had custom settings for @everyone.

Who AutoMod ignores

Bots and people on the whitelist are skipped. You can whitelist a single user or a whole role.

You
-automod whitelist add @Moderators
You
-automod whitelist remove @Moderators
Be careful with big roles. Whitelisting a role that anyone can get, like a self-assigned role, switches AutoMod off for everyone who has it. Keep the whitelist to staff and trusted bots.

Tuning it over the first week

  1. Turn everything on at level 5 and set an AutoMod log channel.
  2. Check the log each day. Look for real people being caught.
  3. If real chat keeps tripping the spam limit, lower the level by one. If spam keeps getting through, raise it by one.
  4. If a trusted person is flagged, whitelist them instead of lowering the whole server's level.

-automods shows your current levels at any time.

If a raid happens

Let the lockdown do its job

You'll see the alert in the system channel. Chat is paused and new joiners are turned away, so the raid can't grow.

Find the accounts

Check the member list and the join logs for accounts that arrived at the same time. -stats members shows the spike.

Remove them

Ban the accounts with -ban [ID] [reason]. Each ban creates a case, and you can ban by ID even if they already left.

Reopen the server

Run -automod raidend once things are calm.

Review the settings

If it triggered on a real burst of new members, like after an announcement, consider lowering the raid level a step.

Things Nexus can't do for you

  • Nexus doesn't read images or files. It checks message text and links.
  • It can only act in channels where it has permission. If a channel is hidden from Nexus, it won't see anything there.
  • It works alongside Discord's own tools. Setting a verification level and using Discord's built-in AutoMod rules in addition adds another layer.

Run a moderation team

How to give your staff the right tools, agree on how to respond, and keep a clear record so everyone is acting the same way.

Decide who can do what

Every command needs a Discord permission. The simplest setup is to give each staff role only the permissions it needs.

LevelPermissionsWhat they can do
HelperKick Members, Moderate Members, Manage MessagesWarn, mute, kick, purge, add notes and look up cases
ModeratorAll of the above plus Ban Members, Manage ChannelsEverything above, plus bans, voiding cases, locking channels
AdminManage Server, Manage RolesAutoMod, logging, roles, giveaways, starboard, prefix

If you'd rather not hand out a Discord permission just so someone can use one command, use Command access to let a single role use a single command.

Agree on an escalation ladder

People are treated more fairly when everyone follows the same steps. Here's a ladder you can copy and adjust.

SituationActionCommand
First small offencePrivate note and a warning-note add, -warn
Repeats after a warningShort mute-mute [user] 60 [reason]
Serious or repeatedLonger mute or a kick-mute, -kick
Harassment or a rule breaker who won't stopTimed ban-ban [user] 7d [reason]
Severe: scams, threats, raidsPermanent ban-ban [user] [reason]

Skip steps when the offence calls for it. A scam link doesn't need a warning first.

Check history before you act

Before handing out a punishment, look at what's already on record. It stops one moderator warning someone for the fifth time without anyone noticing.

You
-cases @Sam
You
-notes @Sam

-cases shows every action on file, and -notes shows private comments from other staff. Cases and history and Staff notes cover both.

Write good reasons

The reason you type is saved in the case, shown in the log, and sent to the member in a DM. Write it so someone reading it a month later understands it without asking you.

  • Good: Posted invite links in #general after being asked to stop
  • Not so good: annoying

Handle mistakes

If an action was wrong, void the case with -casedelete [case number]. That deletes the record and also lifts the ban or the mute it created. It needs Ban Members, so it's naturally limited to senior staff. A deleted case is also written to the moderation log, so there's still a trail showing who removed it.

Use the logs to keep each other honest

  • The moderation log records every action, including warnings, mutes and deleted cases.
  • The messages log records deleted and edited messages, and every time someone uses -say.
  • The users log shows role changes, so you can see who was given what.

Managing an incident in a channel

Slow it down

-slowmode 10 in the channel, or -lock to stop everyone from sending messages while you sort it out.

Clean up

-purge @user 20 removes up to 100 of one person's recent messages. It can't touch messages older than 14 days.

Take action

Warn, mute or ban, with a clear reason. Each action creates a case.

Reopen

-slowmode 0 turns slowmode off and -unlock opens the channel again. -locked lists any channel that's still locked.

Onboarding a new moderator

  1. Give them the staff role, and check it sits below the Nexus role so Nexus can act on the members they act on.
  2. Have them read Moderation and Cases and history.
  3. Walk through your escalation ladder and one real example.
  4. Tell them to run -cases and -notes before acting, and to add a note when something looks like it might come up again.

Transparency for members

Any member can run -myhistory to get their own record sent to their DMs. They can't see anyone else's. It's worth mentioning in your rules, so people know where to look if they're unsure why something happened.

Moderation

Moderation

Kicks, bans, mutes and warnings, plus the tools for tidying up a channel. Every action leaves a record, tells the member why, and shows up in your logs.

What happens when you take an action

Each time you kick, ban, mute or warn someone, Nexus does the same things in the same order:

  1. Checks that you have the right permission and that your role is above theirs.
  2. Checks that Nexus's own role is above theirs.
  3. Carries out the action.
  4. Creates a case and replies with its number.
  5. Sends the member a DM with the reason. If their DMs are closed the action still goes through.
  6. Writes the action to your moderation log, if you've set one up.

Kicking

A kick removes someone from the server. They can come back with a new invite, so it's a way of saying "step back and think about it" without a ban. The person must be in the server.

You
-kick @Sam Spamming invites after a warning
Nexus
👢 Sam has been kicked. Reason: Spamming invites after a warning 📋 Case: `7K3F-92QM-X1RA`

Banning

A ban removes someone and stops them from coming back. You can ban people who aren't in the server, which is useful for repeat offenders and raiders: use their ID. Banned members' past messages aren't deleted.

Timed and permanent bans

Add a length after the user to make the ban temporary. Leave it out for a permanent ban. Nexus remembers timed bans, so they still end on schedule if the bot restarts.

You
-ban @Sam 7d Repeated harassment
Nexus
🔨 Sam is banned for 7d. Reason: Repeated harassment 📋 Case: `7K3F-92QM-X1RA` ⏰ They will be unbanned in 7 days
You
-ban 123456789012345678 Scam links
Nexus
🔨 scammer99 is permanently banned. Reason: Scam links 📋 Case: `B4TH-61DE-ZK9P`

Timed bans accept seconds, minutes, hours and days (see Time formats). Nexus won't ban the server owner, and tells you if someone is already banned.

Unbanning

-unban takes a user ID, which is the most reliable way. Nexus can also find a banned person by username from the ban list.

Muting

A mute uses Discord's own timeout. The member can still read but can't send messages, react or join voice for the length you set. Mutes run from 1 minute up to 28 days, which is Discord's limit. Give the length as a plain number of minutes.

You
-mute @Sam 60 Arguing in #general after a warning
Nexus
🔇 Sam has been muted for 60 minute(s). Reason: Arguing in #general after a warning 📋 Case: `7K3F-92QM-X1RA`
  • If the person isn't in the server, the mute is saved and applies when they join. That stops someone leaving and returning to dodge it.
  • -unmute ends a timeout early, or cancels a saved mute for someone who isn't in the server.
  • Nexus can't time out an administrator or anyone whose role sits above its own.

Warnings

A warning is a recorded "this isn't okay" with no restriction attached. It creates a case, sends the member a DM, and goes in the log. Warnings don't trigger anything automatically, so you decide when a pile of warnings means a mute or a ban. -unwarn removes one if it was a mistake. The person has to be in the server.

You
-warn @Sam Posting spoilers in #general
Nexus
⚠️ Sam has been warned. Reason: Posting spoilers in #general 📋 Case: `7K3F-92QM-X1RA`

Cleaning up a channel

Purging messages

-purge [user] [amount] deletes recent messages from one person in the current channel. You can remove up to 100 at a time. Discord doesn't let bots bulk-delete messages older than 14 days, so anything older stays.

Slowmode

-slowmode [seconds] sets how often each person can send a message in the current channel. -slowmode 0 turns it off.

Locking

-lock stops @everyone from sending messages in the current channel, and -unlock reverses it. -locked lists every channel that's currently locked, which helps you find one you forgot about.

Moderation

Cases and history

A case is the permanent record of a moderation action. This page covers what a case holds, how to look one up, and how to undo one.

What a case is

Kicks, bans, mutes, warnings and their reversals each create a case with its own number, in the form 7K3F-92QM-X1RA. Case numbers are unique, and cases are kept per server, so one server can never see another's.

A case holds:

  • The type of action (kick, ban, mute, warn and so on)
  • The member it was taken against, and the moderator who did it
  • When it happened
  • The reason, and the length if there was one

Looking someone up

  • -automod whitelist remove @user-or-role

Raid lockdown in detail

A lockdown turns off Send Messages for @everyone in every text channel, and saves each channel's previous setting first. Channels that were already locked are skipped. While it's active, anyone who joins is DMed that the server is locked down and then kicked. -automod raidend restores every channel to exactly how it was.

Scam link matching

Nexus looks at the address in each link, not the surrounding text. A match can be an exact domain (and its subdomains), a look-alike address, or a keyword. A harmless site that merely has a similar name, such as one that shares part of a word with a scam site, isn't flagged by the domain rules. Edited messages are re-checked.

Tickets

Tickets give members a private place to talk to your staff. A member presses a button, Nexus creates a channel only they and your support team can see, and the channel is removed when the conversation is over.

How a ticket works

You post a panel

The panel is a message with a green Create Ticket button. You post it once, in a channel members can read, like #support.

A member presses the button

Nexus creates a channel called ticket-username in your ticket category. Only that member, your support role and Nexus can see it. Everyone else, including other members, can't.

Support is pinged

Nexus welcomes the member in the new channel, pings the support role, and adds two buttons: Claim and Close.

You talk it through

Staff can bring in other people if needed, like a second moderator or another member involved in the issue.

Someone closes it

Nexus posts a short record in your log channel, waits five seconds, and deletes the channel.

Setting it up

You need the Administrator permission, a role for your support team, a category for ticket channels, and a log channel. If you haven't made them yet, Set up a new server walks through it.

You

Nexus

The three details come in this order: the support role, the category, then the log channel. If the category's name has spaces, put it in quotes ("Support Tickets") or use its ID. Running setup again later replaces the old settings.

Then go to the channel where members should ask for help and post the panel:

You
-ticket panel
Nexus
🎫 Support Tickets Click the button below to create a support ticket. Our team will assist you as soon as possible. [ 🎫 Create Ticket ]

The panel keeps working after Nexus restarts, so you never need to post it again. You can post it in more than one channel, and every copy opens tickets the same way.

Make the category private

Nexus hides each ticket channel from @everyone by itself, but it's worth setting the category to staff-only as well, so the channels stay hidden even if someone changes a ticket's settings. Give Nexus permission to see and manage the category.

What members see

  • After pressing the button they get a private reply with a link to their new channel, so nobody else sees it.
  • Each member can have one open ticket at a time. If they press the button again, Nexus points them to the one they already have.
  • If a ticket channel is deleted by hand, the member's next press cleans up the old record and opens a fresh ticket.

What staff can do

Staff means anyone with the Manage Channels permission, plus anyone with the support role you chose in setup.

Claiming

Adding and removing people

Adding someone lets them see the channel, send messages and read its history. Removing takes that access away again. Both only work inside a ticket channel, and both tell you if you run them somewhere else.

Closing

Closing is open to anyone who can type in the ticket, including the member who opened it. That's on purpose, so a member can close a ticket once their problem is solved. Nexus says it's closing, writes this to your log channel, and deletes the channel five seconds later:

  • the channel name
  • who opened the ticket
  • who closed it
Nexus doesn't save a transcript. Once the channel is deleted, the conversation is gone. If you need to keep it, copy what matters, or use a note on the member with -note add, before closing.

  • Manage Channels, to create and delete ticket channels.
  • Manage Roles, to set who can see each channel.
  • View and Send Messages in the panel channel and the log channel.

  • Keep the panel channel read-only for members, so it stays a clean place with just the button.
  • Give the support role to people who answer tickets, and Manage Channels only to people you'd trust with channels generally.
  • Add a short line to the panel channel's description about what belongs in a ticket, like ban appeals, reports and questions.
  • Use the log channel to see how often tickets open and who handles them.

The rules for every role command

Every command here needs Manage Roles, and these rules apply to all of them.

  • Nexus can only give or take roles that sit below its own role. Move the Nexus role up in Server Settings if it says it can't.
  • You can only use roles that sit below your own top role. The server owner is exempt.
  • You can't change the roles of someone whose top role is equal to or above yours. If you try, Nexus says so by name.
  • Roles managed by an integration, such as a bot's own role or a booster role, can't be handed out or removed. The @everyone role is always left alone.

When a role is refused, Nexus tells you which ones and why, instead of failing quietly:

You

Good to know

  • Nexus checks for expired roles once a minute, so a role can last up to a minute longer than the time you set.
  • Timers are saved, so they still end on time if Nexus restarts.
  • Giving the same timed role again replaces the old timer, so you can extend someone by running the command again.
  • If the person leaves the server before it ends, the timer is dropped, since there's nothing left to take away.
  • If the role is deleted, the timer is dropped too.

Trusted members

  • Mark their special roles as persistent
  • A short break from the server doesn't cost them anything

Trial staff

Command access

Every command has a normal rule for who can use it. Command access lets a server administrator change that rule for a single command, so you can let a role use something without giving that role a Discord permission it doesn't otherwise need.

The normal rules

Out of the box, each command needs a Discord permission, like Kick Members or Manage Server. The command list shows the permission for every command, and commands marked "Everyone" need nothing.

That's fine for most servers, but it can be clumsy. If you want helpers to be able to mute but not kick, you'd have to hand out Moderate Members to people who may not need any other permission. Command access solves that.

Changing access

The command is -permission [command] [role, user or permission], and it needs the Administrator permission. It does one of three things depending on what you give it as the last part.

You give itExampleResult
A role-permission ban @ModeratorsEveryone with that role can use the command, even without the usual permission.
A person-permission mute @SamThat one person can use the command.
A permission-permission mute Moderate MembersThe command now needs that permission instead of its usual one.
You
-permission warn @Helpers
Nexus
✅ @Helpers can now use `-warn`, even without the usual permission.

Running the exact same thing again takes it back off, so the same command both adds and removes.

You
-permission warn @Helpers
Nexus
Took @Helpers off `-warn`. They need the usual permission again.

Checking what's set

Give only the command name to see its current access.

You
-permission warn
Nexus
Access for -warn Roles that can always use it: @Helpers

If nothing has been changed, Nexus says the command "is using its normal access rules".

Writing the command name

  • Leave off the prefix. Write ban, not -ban.
  • Use the full name for commands with parts. Access is set per part, so write giveaway start, role add or ticket close, and set each part you want to open up.
  • A permission can be written many ways. Moderate Members, moderate_members and moderate-members all work, and Manage Server works for Manage Guild.
You
-permission giveaway start @Events
You
-permission giveaway end @Events
You

What access does and doesn't change

Command access replaces the Discord permission check and nothing else. Everything that keeps your server safe still applies:

  • The role-order rule still holds. A helper who is allowed to use -ban still can't ban someone above them.
  • Nexus still needs its own permissions to do the job, and its role must still be above the person it's acting on.
  • Cases and logs are still written, with the real moderator's name on them.

A few commands decide who can use them in their own way instead of through a Discord permission, like -ticket add and -ticket remove, which check for the support role. Command access can't change those.

What can't be changed

For safety, the access for these commands is fixed: -permission itself, -wipe, -commands, -help and -ping. Nexus's owner-only commands are fixed too. If you try, Nexus says "that command's access can't be changed".

Seeing it in the commands menu

If you change which permission a command needs, -commands in your server shows the new permission, so your team sees the real rule instead of the default.

Starboard

The starboard collects the best messages in your server in one channel. When someone reacts to a message with the emoji you choose, Nexus reposts it there, so the funny, helpful and memorable moments don't get buried.

How it works

  1. You pick an emoji and a channel.
  2. A member reacts to any message with that emoji.
  3. Nexus posts a copy of the message in the starboard channel, with a link back to the original.
The first reaction is enough. There's no minimum number of reactions. The moment anyone reacts with the starboard emoji, the message is posted. Choose an emoji that members understand means "this deserves the board", and not one they'd use casually.

Setting it up

You need the Manage Server permission, and a channel for the board.

You
-starboard setup ⭐ #starboard
Nexus
Starboard is set up. Messages with ⭐ will be posted to #starboard.

You can use a normal emoji or a custom emoji from your server. Run the command again to change the emoji or the channel, and -starboard on its own to see what's set. Anyone can run that check.

What gets posted

  • The author's name and avatar, and the message text (long messages are shortened).
  • A Jump to message link and the channel it came from.
  • The reaction count at the moment it was posted.
  • The first attached image, if the message has one.

Each message is posted once. More reactions later don't create a second copy, and the count on the repost isn't updated afterwards.

What's ignored

  • Reactions from bots.
  • Messages in the starboard channel itself, so the board can't repost itself.
  • Messages in direct messages.
  • Other emoji. Only the one you chose counts.

If Nexus can't post to the starboard channel at that moment, it forgets that it tried, so the next reaction on the message tries again.

Permissions

Nexus needs to view and send messages and embeds in the starboard channel, and to read the messages people react to. Make the starboard channel read-only for members, so it stays a gallery.

Tips

  • Explain the emoji in your rules or a pinned message, so members know how to nominate something.
  • Use a separate starboard per theme by keeping the emoji distinctive, like 🌟 for memorable moments.
  • If someone abuses it, a moderator can delete the repost from the board. The original is untouched.
  • Reactions on very old messages may not trigger it, since Nexus works from messages it has seen recently.

  • people who are no longer in the server

Challenging a friend

  1. Open the game's lobby and pick your friend from Challenge a friend.
  2. Nexus posts the challenge in the channel and pings them.
  3. They have one minute to accept or decline. If they don't answer, the challenge expires.
  4. If they accept, the game starts straight away, and only the two of you can press its buttons.

You can't challenge yourself or a bot. Someone Nexus has blocked from games can't be challenged either.

During a game

  • Games run on buttons, and only the people playing can use them. Anyone else who tries is told it's not their game.
  • You have about two minutes of inactivity before a game times out. In a game against a friend, the person who stopped playing loses and the other person takes the win. Against Nexus, the game is just closed.
  • When a game ends, a Play again button appears for 90 seconds. In games where the first move matters, it swaps who goes first.

Stats

Stats shows how active your server is: who's talking, where, when people are in voice, how many joined and left, and which invites bring people in. It's a view of the last 30 days, with graphs.

How it works

Once Nexus is in your server, it counts activity quietly in the background. It never stores what people say. It only records that a message happened, who sent it and in which channel, and how long people spent in voice channels.

  • Text. Each message from a person adds to their count and their channel's count. Bots are ignored.
  • Voice. Time in a voice channel is added when someone leaves or switches channel. Visits shorter than 10 seconds aren't counted.
  • Joins and leaves. Counted from the moment Nexus joined, along with which invite was used.
Stats start when Nexus does. Nexus can't see activity from before it joined your server, so a brand-new server shows little until a few days have passed. Every stats page only covers the last 30 days.

Invite stats

Invite tracking answers "which invite brought these people here?" Give -stats invite the code from an invite link, which is the part after discord.gg/.

  • Nexus needs the Manage Server permission to see which invite someone used when they join. Without it, joins still count but aren't tied to an invite.
  • It can only tell you about invites for your own server. A code from another server gets a "can't find that invite" reply.
  • The numbers cover joins Nexus has seen, so an older invite may show fewer joins than Discord does.

Reading the numbers well

  • Ranks compare people within your server over the last 30 days only, so they move as people's habits change.
  • The graph shows one point per day. A flat line means nobody was active, or Nexus hadn't started counting yet.
  • Member counts come from joins and leaves Nexus witnessed, and the "current members" figure comes straight from Discord.

Reminders

Ask Nexus to remind you about something later, from a few minutes to a full year. When the time comes, Nexus pings you where you asked.

Setting a reminder

Anyone can use reminders. Give it a length of time, then the text to remind you about.

You
-reminder create 1h30m Take the pizza out
Nexus
✅ Reminder set Reminder: `Take the pizza out` I will remind you: in 2 hours (Tue, Nov 17, 2026 6:42 PM) Channel: #general

The time can be seconds, minutes, hours, days, weeks, months or years, and you can combine them like 1d12h. The longest is one year. Time formats lists everything it understands.

When it's time

  1. Nexus posts the reminder in the channel where you set it, and pings you.
  2. If it can't post there anymore (the channel was deleted, or it lost permission), it sends you a direct message instead.
  3. If neither works, because your DMs are closed and the channel is gone, the reminder is dropped.

Reminders set in a DM with Nexus come back to that DM.

Nexus checks every 30 seconds, so a reminder can land up to half a minute after the exact time. Reminders are saved, so they still arrive if Nexus restarts.

Translate

Anyone can translate text between languages, with the language names written out in full.

You
-translate English Spanish Where is the library?
Nexus
🌐 Translation Original (English): Where is the library? Translated (Spanish): ¿Dónde está la biblioteca? Translated with Google Translate

The order is the language you're translating from, the language you want, then the text. The text can be up to 1,000 characters, and Nexus tells you if it's too long. If a language name isn't recognised, Nexus asks you to check both names.

Say

-say [channel] [message] posts a message as Nexus in another channel. It needs Manage Messages, and it's useful for announcements, rules and giveaway notes.

You
-say #rules Rules updated, please have a read!
Nexus
(posts in #rules and removes your command)
  • Messages can be up to 2,000 characters, which is Discord's own limit.
  • It can mention people, but never @everyone, @here or roles, so it can't be used to mass-ping.
  • Nexus deletes your command message afterwards so only the bot's message is left.
  • If logging is on, each use is recorded with who ran it. See Logging.
  • Nexus needs permission to send messages in the destination channel, and tells you if it can't.

Prefix

The prefix is the character you type before a command. It starts as -, and you can always mention Nexus instead (@Nexus ping).

You
-prefix set !
Nexus
Done. My prefix here is now `!`.
  • -prefix shows the current prefix. Anyone can ask.
  • -prefix set [prefix] changes it, and needs Manage Server.
  • A prefix can be up to 5 characters, with no spaces, and it can't start with <.
  • The prefix is per server, so changing it doesn't affect any other server.
If the prefix clashes with another bot, change Nexus's rather than guessing. And if you ever forget the new one, mention Nexus with @Nexus prefix and it will tell you.

Throughout these docs, commands are written with the default -.

Ping

-ping replies with how long Nexus takes to respond, in milliseconds. It works in server channels and in DMs. Use it to check that Nexus is online and responsive before reporting a problem.

Troubleshooting

Most problems come down to a missing permission, a role in the wrong place, or a typo in a command. Start with the checks below, then find your symptom.

First, run these checks

Is Nexus online?

Run -ping. If there's no reply, Nexus may be offline or can't see or speak in that channel. Try another channel.

Are you using the right prefix?

Mention Nexus and say prefix: @Nexus prefix. It always answers, even if the prefix was changed.

Is Nexus's role high enough?

In Server Settings, Roles, drag the Nexus role above any role it needs to manage, or above people it needs to act on.

Does Nexus have the permissions?

Check the channel, not only the server. A channel's own settings can block the bot even when its role allows it.

Nexus doesn't respond to commands

  • Nexus must be able to view the channel and send messages in it.
  • Check the prefix. A change with -prefix set applies to the whole server.
  • In DMs only -ping, -commands and -help work.

"You do not have permission"

The command needs a permission you don't have. The command list shows what each one needs, and -commands shows the permissions as set in your server. If your server owner wants you to be able to use it without extra permissions, they can grant it with command access.

AutoMod and logging

  • AutoMod isn't catching anything. Check the rule is set up for your server, and that the person or one of their roles isn't on the AutoMod whitelist. See AutoMod.
  • AutoMod is deleting too much. Loosen the limit, or whitelist the role or person. Raise the number gradually.
  • Nothing appears in the log channel. Nexus needs to view and send messages and embeds there. Re-run the -log command for that event and confirm the channel. See Logging.

Tickets, roles and giveaways

  • The ticket button does nothing. Make sure setup was done with -ticket setup and that Nexus has Manage Channels and Manage Roles. See Tickets.
  • A role can't be given. The role is above Nexus's role, above yours, or managed by an integration. See Roles and autoroles.
  • A timed role lasted a bit longer. Expiry is checked once a minute.
  • The giveaway has no 🎉. Nexus needs Add Reactions in that channel. Start it again after fixing it.
  • The giveaway or reminder came late. Both are checked about every 30 seconds.
  • Starboard isn't posting. Check -starboard for the emoji and channel, and that Nexus can send embeds there.

Games and stats

  • Game buttons say it isn't your game. Menus belong to whoever opened them. Run -games for your own.
  • The buttons stopped working. Games and menus time out after a couple of minutes. Start again.
  • Stats are empty. They start counting when Nexus joins and show 30 days at most. See Stats.
  • Invite stats show nothing. Nexus needs Manage Server to track invites, and the code has to belong to your server.

Reading error messages

Nexus tries to say what went wrong in plain words. A message that starts with "I can't" or "I couldn't" usually means a missing permission or a value it couldn't read. Read it fully before trying again, because it normally names the exact thing to fix.

Still stuck?

Join the support server and tell us:

  • the exact command you ran, and the reply (a screenshot is great)
  • what you expected to happen
  • your server's ID and the channel, if the problem is channel-specific

Never share your bot token, passwords or private messages when asking for help. Nobody on the team will ever ask for them.

Data wipe

If you want everything Nexus has stored about your server deleted, the server owner can ask for it with one command. This page explains exactly what happens, step by step.

Who can do it

Only the server owner. Nobody else, not even an administrator, can start a wipe or press the confirmation buttons. If someone else runs -wipe, Nexus says only the server owner can use it. It must be run in a server, not in a DM.

What gets deleted

  • Moderation cases and member history
  • Staff notes
  • Message, voice, join and leave stats
  • AutoMod, logging, ticket and autorole settings
  • Command permission changes
  • Giveaways, reminders, starboard settings and your custom prefix

After a wipe, Nexus stays in your server and starts fresh, like a newly added bot. If you want it gone entirely, kick it afterwards.

A wipe can't be undone. Once it is processed, none of this can be brought back. Make a note of anything you need first, like case history for an appeal.

How the request works

Run the command

The owner types -wipe. Nexus lists everything that would be erased and asks you to confirm.

Confirm twice

The first screen has I understand, continue and a cancel button. A second "last warning" screen asks again with Yes, create my request. Either screen lets you cancel, and nothing changes if you do.

Get your request number

Nexus creates a request for your server and shows you a code. Nothing has been deleted at this point. It is only a request.

The team carries it out

The Nexus team gets the request and processes it. Once it's processed, all stored data for your server is permanently deleted.

Each confirmation screen waits for two minutes. If you don't answer in time, nothing is changed, and you can run -wipe again whenever you like.

Keep your request number

The number identifies your request. Keep it somewhere safe. If you want to check on it, or change your mind and cancel it before it's processed, share the number in the support server.

One request per server

Each server can have one request. If you run -wipe while one is waiting, Nexus tells you it's already on file. If a wipe was already completed, Nexus tells you when it happened. For another one, ask the support team.
